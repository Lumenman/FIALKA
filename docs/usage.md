# Работа с программой

```
fialka [-e|-d|-p] -k ключ.txt [ключи] [вход.txt]
fialka --genkey | --genpos | --selftest
```

Вход — файл аргументом или stdin, выход — stdout или `-o`. Всё в UTF-8.

| ключ | что делает |
|---|---|
| `-e` / `-d` / `-p` | зашифрование (по умолчанию), расшифрование, сквозной прогон |
| `-k`, `--key ФАЙЛ` | ключ дня в формате перфокарты |
| `--pos "..."` | ключ сообщения: 10 букв начальной установки |
| `--mode L\|M\|N` | режим текста, рычаг Б/С/Ц (принимаются и русские буквы) |
| `-M`, `--machine` | файл машины, по умолчанию `../data/machine-M125-3.ini` |
| `-H`, `--head` | перебить печатающую головку, заданную строкой `script` |
| `-w`, `--wheels` | перебить комплект, заданный в ключе |
| `-o ФАЙЛ` | выходной файл |
| `--log ФАЙЛ` | подробная трасса |
| `--prepare` | подготовить текст по `data/prepare.ini` |
| `--genkey`, `--genpos`, `--set`, `--seed` | генерация ключей |

Направление работы и режим текста — ключи командной строки, а не поля файла:
на машине это тумблеры оператора, а не ключ дня.

## Обычный обмен

```bash
fialka --genkey --set 6K -o key.txt     # ключ дня: сутки, вся сеть
fialka --genpos                         # ключ сообщения: одноразовый
                                        # -> Б Щ Щ Е Н   Д Ы Ч Ч Ы

fialka -e -k key.txt --pos "Б Щ Щ Е Н   Д Ы Ч Ч Ы" msg.txt
fialka -d -k key.txt --pos "Б Щ Щ Е Н   Д Ы Ч Ч Ы" cipher.txt
```

Начальная установка передаётся вместе с шифртекстом: без неё получатель
расшифровать не сможет, а если её не менять, все сообщения дня пойдут с одного
старта — ровно та ошибка, на которой ломали Энигму.

`--seed N` делает генерацию воспроизводимой. Источник случайности — `Random`
из RTL, **не криптографический**: для реконструкции музейной машины годится,
для боевого ключа нужен другой.

## Режим текста

Рычаг Б/С/Ц на машине, ключ `--mode` в программе. Шифр в буквенном и
смешанном одинаков, разница только в печати (см. [mechanism.md](mechanism.md)).

```bash
fialka -e -k key.txt msg.txt                      # L: буквы, по умолчанию
fialka -e -k key.txt --mode M msg.txt             # M: цифры и знаки через ЦФ/БК
fialka -e -k key.txt --mode N -                   # N: только цифры
```

В смешанном режиме переключения регистра расставляет программа — по самим
знакам текста, как это делал оператор. Разметки в файле не нужно:

```
$ printf 'АБ12ВГ' | fialka -e -k keys/kt16_08_26.txt --mode M
РКБЗНДКИ
```

Восемь букв на шесть знаков: ЦФ перед цифрами, БК после них — они шифруются
наравне с текстом. Обратно `-d --mode M` даёт `АБ12ВГ`, переключения
печати не дают. В конце сообщения головка возвращается к буквам.

В режиме цифр вход и выход — цифры, пробелы во входе можно ставить для
разбивки на группы, они пропускаются:

```
$ printf '24310' | fialka -e -k keys/kt16_08_26.txt --mode N
36161
```

## Знаки не из алфавита

На машине 30 контактов, но набирается на них разное — смотря какой режим:

| вход | L (буквы) | M (смешанный) | N (цифры) |
|---|---|---|---|
| строчные буквы | молча вверх | молча вверх | — |
| `\r`, `\n` | пропускаются | пропускаются | пропускаются |
| пробел | контакт 30 | контакт 30 | пропускается: контакт мёртв |
| цифры | отказ | набираются | единственное, что можно |
| `. , : - " % / + = ° ; N` | отказ | набираются | отказ |
| Ъ, Э, Й | отказ | набираются через ЦФ | отказ |
| Ф, Ж | обычные буквы | через ЦФ: клавиши заняты под ЦФ и БК | отказ |
| Ё | отказ | отказ | отказ |
| Й при расшифровании | контакт 30 шифртекста | то же | — |

Отказ снимается ключом `--prepare`: он заменяет по `data/prepare.ini` только
то, что в этом режиме не набирается. В буквенном `.` станет `ТЧК`, в
смешанном пройдёт как есть.

Отказ — **всё или ничего**: код возврата 1, наружу не выходит ни куска
шифртекста, ни в stdout, ни в `-o`. Иначе обрубок можно было бы принять за
готовое сообщение.

```
$ printf 'ПРИВЕТ, МИР' | fialka -e -k key.txt
ошибка: знак 7 (,): такого знака на машине нет, готовьте текст ключом --prepare

$ printf 'Привет, мир.' | fialka -e -k key.txt --prepare
подготовка: знак 7  , -> ЗПТ
подготовка: знак 12  . -> ТЧК
ФСИЮФГИТЮВХКЦФФ
```

Каждая замена печатается в stderr: молча менять сообщение нельзя, получатель
расшифрует не то, что отправляли. Номера знаков — по исходному тексту.
На шифртексте `--prepare` запрещён: он подменил бы Й.

## Печатающая головка

Знаки живут на головке, шифр — на дисках, и эти две вещи не связаны: диски и
рефлектор считают номера контактов, а какая буква на контакте нарисована, им
безразлично. Поэтому головку можно сменить целиком.

Штатную называет строка `script` в файле машины (`script = cyrillic` →
`data/head-cyrillic.ini`). Ключ `-H` подставляет другую:

```bash
fialka --genkey -H ../data/head-poland.ini --set 6K -o lat.txt
fialka --genpos -H ../data/head-poland.ini     # -> 17 3 22 26 9   4 16 18 27 14

fialka -e -H ../data/head-poland.ini -k lat.txt --mode M \
       --pos "17 3 22 26 9   4 16 18 27 14" msg.txt
```

`-H` нужен и генераторам ключей: ряды карты они печатают знаками нижнего ряда,
и без него вышла бы кириллица. Латинские головки — исключение: в их нижнем
ряду есть цифры, и `5` на карте не отличить от числа 5, поэтому под ними ключ
печатается числами. Но на шифр головка не влияет — знаки в ключе это запись
чисел, а не часть механизма. Кириллический ключ с латинской головкой не
прочитается (буквы не разрешатся, будет отказ), зато тот же ключ, переписанный
числами, годится под любую головку:

```bash
# ряды карты и начальная установка числами — головке безразличны
fialka -e -H ../data/head-poland.ini -k key.txt --pos "7 6 2 1 9   4 5 10 3 8"
```

Режим цифр (`--mode N`) работает только с кириллической головкой: какие десять
клавиш отпираются, задаёт проводка машины, а не головка, и у латинских цифры
стоят не на них. Обе реализации в этом случае отказываются вслух; почему — в
[mechanism.md](mechanism.md), раздел про страновые головки.

Проверено на `demo/`: открытый текст, переписанный контакт в контакт
латиницей и зашифрованный польской головкой на том же ключе (переписанном
числами), после обратной замены даёт `demo/en.txt` знак в знак. Смена головки —
переклейка, а не второй шифр, и считать её дополнительной защитой нельзя.

Формат головки и проверки при загрузке — в [formats.md](formats.md).

## Трасса

`--log ФАЙЛ` пишет по строке на каждый узел прохождения знака:

```
--- знак 1: контакт 15
  поз     7  6  2  1  9  4  5 10  3  8   щупы -##..###.-
  kb     15>24
  круг 1 вниз   card 24>24  entry 24>29  диски 10:3 9:19 ... 1:26  refl 26>30
  круг 1 вверх  рефлектор >30  диски 1:19 ... 10:13  entry' 13>12  card' 12>12  kb' 12>20
  =      контакт 20 = Ф
  шаг    вперёд 9,7       назад 2           поз  7  5  2  1  9  4  6 10  4  8
```

`щупы`: `#` — штифт под щупом, `.` — нет, `-` — слот не опрашивается.
При мёртвом контакте рефлектора появляется `круг 2` — сигнал ушёл в барабан
на новый круг. Видно при `--mode N`: при тридцати живых контактах у рефлектора
мёртвых нет. В трассе знаки нумеруются по нажатиям, поэтому в смешанном режиме
там видны и вставленные ЦФ с БК.

При отказе лог остаётся с частичной трассой: это диагностика, и правило
«всё или ничего» на неё не распространяется.

## Проверки

```bash
cd pascal && fpc -O2 fialka.pas && ./fialka --selftest
cd reference && python fialka.py --selftest
python crosscheck.py 300
```

`--selftest` в каждой реализации:

1. **Сквозной прогон.** В режиме `-p` рефлектор тождественный, значит
   `F = A⁻¹ ∘ I ∘ A = I`: машина обязана возвращать вход. Ловит любую ошибку в
   прямом и обратном проходе, во входном диске, в перфокарте и в обратных
   таблицах.
2. **Обратимость.** Зашифрование и расшифрование при одинаковом старте обязаны
   быть взаимно обратны. Отдельно — в смешанном режиме и в режиме цифр, вместе
   с автоматикой регистра: текст обязан пройти туда и обратно вместе с
   вставленными ЦФ и БК.
3. **Разбор ключа** (оракул): ключи для первых двух проверок генерируются в
   формате карты и читаются обратно, плюс кривые ключи обязаны отвергаться.
4. **Сверка с `demo/`** — регрессионный вектор, см. `demo/note.txt`.
5. **Векторы с оригинала** — `demo/vectors.txt`, три режима текста, оба
   направления. Эти пары сняты с `M125v5_16eng.exe`, поэтому доказывают
   совпадение с оригиналом, а не только неизменность поведения.

`crosscheck.py` гоняет обе реализации на случайных ключах и сравнивает знак в
знак: три комплекта, три режима текста, зашифрование и расшифрование, и ключи
генерируются попеременно обеими реализациями, чтобы каждый разбор читал чужой
вывод. Отдельным набором сверяются подготовка текста и отказы.
