# Эталонная модель на Python

Оракул для реализации на Паскале: медленно, зато формулы записаны буквально
так, как они разобраны в [docs/mechanism.md](../docs/mechanism.md), и по ним
можно сверять быструю реализацию.

```
fialka.py          модель, самопроверки, консольный интерфейс
crosscheck.py      сверка обеих реализаций на случайных ключах
extract_tables.py  одноразовый: deco/M125v5_16eng.exe -> ../data/*.ini
```

## Запуск

```bash
python fialka.py --selftest
python fialka.py -e --key ../keys/kt16_08_26.txt --in ../demo/de.txt
python crosscheck.py 300
```

Ключи командной строки те же, что у реализации на Паскале, кроме `-o` и
`--log`; вход задаётся ключом `--in`. См. [docs/usage.md](../docs/usage.md).

## Откуда данные

`../data/*.ini` порождаются из бинарника: `python extract_tables.py`. Штифты
извлекаются по номеру контакта, а не по порядковому номеру штифта — это
единственное место, где легко ошибиться незаметно.

Проводка комплектов 6K и 3K хранится в бинарнике «перевёрнутой» относительно
той конвенции, в которой записан 5K: `W₂(x) = −W₁⁻¹(−x)`. Это расхождение
конвенций внутри самих данных, а не свойство машины; используется то, что
лежит в бинарнике, и сторона сердечника из ключа читается как есть.
