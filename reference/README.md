# Эталонная модель Фиалки М-125

Реализация механизма, восстановленного из `deco/M125v5_16eng.exe` и сверенного
с `Fialka_200.pdf` (Reuvers & Simons, v2.0). Написана как **оракул**, а не как
продукт: медленно, зато формулы буквально повторяют документ по механизму,
чтобы по ней можно было сверять быструю реализацию.

```
reference/
  fialka.py            модель, самопроверки, консольный интерфейс
  extract_tables.py    одноразовый: exe -> data/*.ini
  data/
    machine-M125-3.ini входной диск, рефлекторы, клавиатуры, алфавит, щупы
    wheels-3K.ini      комплект дисков (Польша)
    wheels-5K.ini      комплект дисков (Венгрия)
    wheels-6K.ini      комплект дисков (Чехословакия)
  keys/
    kt16_08_26.ini     ключ с перфокарты из demo/
```

## Запуск

```bash
python fialka.py --selftest
python fialka.py --key keys/kt16_08_26.ini --in ../demo/de.txt
```

По умолчанию берётся `data/machine-M125-3.ini` и `data/wheels-6K.ini`;
другой комплект — через `--wheels data/wheels-3K.ini`.

## Самопроверки

Обе не требуют эталонных данных и проходят:

1. **Режим `plain` обязан быть сквозным.** Рефлектор тождественный, значит
   `F = A⁻¹ ∘ I ∘ A = I`. Ловит любую ошибку в прямом и обратном проходе,
   во входном диске, в перфокарте и в построении обратных таблиц.
2. **Обратимость.** `coding` и `decoding` — взаимно обратные таблицы
   рефлектора, поэтому шифрование и расшифрование при одинаковом старте
   обязаны быть взаимно обратны.

Второй тест использует только 29 букв: Й набрать нельзя, её клавиша занята
пробелом (см. ниже).

## Пробел и буква Й

Алфавит — ровно 30 знаков, пробела в нём нет. Пробел делит клавиатурный контакт
с буквой **Й**, тридцатой и самой правой:

- в `coding` пробел на входе становится контактом 30, а на выходе контакт 30
  печатается как Й;
- в `decoding` наоборот: Й на входе, пробел на выходе;
- Й в открытом тексте — ошибка оператора: в оригинале её заранее заменяли на И.

## Откуда данные

`data/*.ini` порождаются из бинарника: `python extract_tables.py`. Адреса и
обоснование — в документе по механизму, раздел «Карта адресов». Штифты
извлекаются по номеру контакта (атрибут `id` в XML Cryptomuseum, не `s`) —
совпадение с XML побитное для всех трёх комплектов.

Проводка 6K и 3K в бинарнике хранится в «перевёрнутом» виде относительно XML
(`W₂(x) = −W₁⁻¹(−x)`), 5K — как в XML. Это расхождение конвенций между
источниками, а не свойство машины; здесь используется то, что в бинарнике.

## Сверка с оригиналом

`demo/de.txt` → `demo/en.txt` воспроизводится **знак в знак, 24 из 24**, на
ключе `keys/kt16_08_26.ini` и комплекте 6K. Демо снято с самой программы, а не
построено этой моделью, поэтому это и есть подтверждение, что механизм совпал.

Проверка входит в `--selftest` и падает, если что-то сломается.

### Как читается перфокарта

На карте пять строк, а машине нужно шесть массивов. Шестая величина —
стартовая позиция; это буквы, видимые в прорези барабана, и программа
выставляет их равными строке 1 (`FUN_00469aec`, режим 0:
`position[i] = wheel_order[i]`).

| строка карты | массив |
|---|---|
| 1 | `wheel_order` — обод по слотам, перестановка 1..10 |
| 2 | `ring` — установка кольца |
| 3 | `core_order` — сердечник по слотам, перестановка 1..10 |
| 4 | `core_side` — сторона сердечника, 1 или 2 |
| 5 | `core_offset` — смещение сердечника |
| прорезь | `position` — стартовая позиция, здесь равна строке 1 |

Настройки машины — из `deco/M125.INI`: `Serie=6` (6K), `Module=30`,
`B-S-C=1` (буквы), `Machine type=1`, `Keyboard=5`, `RUS LAT=2`.
Перфокарта (`card`) при съёме демо была тождественной.

### Побочное подтверждение формулы стороны сердечника

Сошлись **две** конфигурации, и они эквивалентны:

- проводка из бинарника, `core_side` как на карте;
- проводка из XML Cryptomuseum, `core_side` инвертирована (1↔2).

Это ровно то, что предсказывает `W₂(x) = −W₁⁻¹(−x)`: два источника расходятся
в том, какую сторону считать первой, и разница гасится переворотом стороны.
